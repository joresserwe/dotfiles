# Codex 공통 기본값

이 규칙은 모든 Codex 세션·프로젝트의 현재 에이전트와 위임된 자식 작업에 적용한다. 사용자의 범위를 보존하고, 기존의 무관한 변경은 건드리지 않는다.

## 토큰과 탐색

- 검색은 우선 `rg`로 하고, 관련 파일만 필요한 만큼 읽는다.
- 출력, 위임 컨텍스트, 설명은 짧고 작업에 필요한 범위로 제한한다.
- 이미 성공한 검증은 새 증거가 없으면 반복하지 않는다.
- 작은 작업에 계획·리뷰 자식을 추가하지 않는다. 필요한 경우 기존 에이전트를 재사용하고, 중복되는 full-history fork를 피한다.

## 검증 배치

- 각 파일·패치·코드 작성 직후에 테스트·린트·빌드를 반복 실행하지 않는다.
- 의미 있는 기능·수정 묶음 또는 작업 마무리 시점에 관련 변경과 필요한 검증을 모아 최소 범위로 한 번 수행한다.
- 실패사항을 모아서 수정하고 실패·영향 범위만 재검증한다. 변경이 없으면 성공한 검사를 반복하지 않는다.
- 사용자가 명시했거나 다음 구현을 막는 오류 원인을 확인해야 하는 경우에만 좁은 중간 검증을 허용한다. 테스트를 아예 생략하는 규칙은 아니며, 완료 전에 필요한 검증은 유지한다.

## 모델 라우팅

- 기본 모델은 `gpt-6-astra`의 `xhigh`다. Astra(입력 별칭 `astro`)가 문제 정의·분석·계획·조사·설계·중요 판단과 맥락 의존적이거나 복잡한 구현·검증을 직접 수행하고 최종 결과를 책임진다.
- `gpt-5.6-luna`의 `xhigh`는 변경 위치·방법·기대 결과가 이미 확정된 단순·기계적인 코드·설정·스크립트·테스트 수정과 그 좁은 검증에만 사용한다. 위임·재설명·검토 비용보다 절감이 있을 때만 선택하고, 바로 끝나는 사소한 수정 때문에 자식을 강제 생성하지 않는다. 불확실성을 발견하면 임의로 범위를 넓히지 말고 근거와 함께 부모에게 반환한다.
- `gpt-5.6-sol`의 `high`는 질문·대상·기대 산출물이 명확한 독립 읽기 전용 분석·조사에 한해 위임한다. 문제 정의·분석 방향·개선 우선순위는 Astra가 책임지며, Sol은 근거·한계·불확실성을 반환하고 자동으로 Luna에 구현을 넘기지 않는다.
- `Terra`는 자동 라우팅에서 제외하며 사용자가 명시적으로 요청한 경우에만 사용한다. `gpt-5.6-terra` 프로필은 유지한다.
- 이 지침은 위 조건을 만족하고 위임 이점이 있는 좁은 하위 작업의 위임을 요청한다. 핵심 분석은 Astra가 직접 수행한다. 모델과 추론 수준은 실제 배정 기준으로 명시하고, 지정 시 `fork_turns=none` 또는 충분한 최소 컨텍스트를 사용하며 불필요한 full-history fork를 피한다. 실제 라우팅이 불가능하면 문구만으로 전환했다고 주장하지 말고 구체적인 수동 실행 명령을 제시한다.
- 글로 모델을 지시한다고 실제 부모 세션의 모델이 바뀌지는 않으며, 실제 라우팅과 권한은 설정과 모델 배정을 기준으로 확인한다.

## 기본 보고

최종 보고는 한국어로 간결하게 작성하고, 변경 파일·핵심 동작·검증 결과·남은 제한만 포함한다.

## 주석

- 기본은 불필요한 새 주석을 쓰지 않는다. 코드 자체로 알 수 있는 내용, 수정 서사·자기 정당화·변경 이유, 삭제된 코드의 흔적은 주석으로 남기지 않는다.
- 현재 코드만 읽어서는 알 수 없는 관측 실패, upstream issue, 필수 순서, 비자명한 단위·형식·인코딩만 새 주석으로 허용한다.
- 기존 주석 중 현재 코드에 유효한 위 근거는 보존한다. 주석 hook은 이를 환기하는 자문이며 의미 판단이나 강제 삭제를 수행하지 않는다.
